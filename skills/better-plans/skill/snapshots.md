# Snapshots

Read when the user asks for a snapshot, or says the page looks out of date to someone who can't sign in (SKILL.md's routing table).

The page's own HTML is a snapshot: what someone who can't load the database sees (signed out, or a tool that doesn't run the page's script) and what the version history keeps. Updates don't change it. A snapshot writes the records into the entries and republishes the page. **The page saves one by itself** when the owner or an editor opens a plan that has changed since its snapshot and the snapshot is over a day old or more than 30 records behind; the line under the summary then says "Snapshot saved automatically" with the time. Otherwise that line says when the last snapshot was taken and whether the plan has changed since, beside a **Save Snapshot** button. When the user asks for a snapshot, tell them opening the plan saves one if it's due, and the button saves one now. If they want Claude to do it: list `plan` and `statuses` (with `out_dir`, note the versions), run `plan.py snapshot <scratchpad>/db --out <scratchpad>/snap.html --fold <scratchpad>/fold`, send the writes it prints in that order (fill in `if_version` from the list), then publish the page with the plan's `url` after an Artifact `read` without `path` (the page must be viewed first). The outline mentions it when more than 30 records are waiting, which means nobody who can edit has opened the page since.
