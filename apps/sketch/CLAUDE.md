# Sketch

A fast, simple Windows paint app (a modern Microsoft Paint). It lives in `apps/sketch` of the toolbox repo; read the root CLAUDE.md and this folder's README too. Its CI workflow is `.github/workflows/sketch.yml` at the repo root, and the release workflow builds its installer with `build.ps1`.

Design decisions for each phase, and why, are in [docs/decisions.md](docs/decisions.md). Read the section for the part you're changing first.

## Checks

The local checks of the real app are `check:native` (73 checks), `check:speed`, `check:fuzz`, `check:update` (8 checks; README, Build and Check) and the timings `npm run perf`. A tool or command not built yet goes in `src/tools/registry.ts` or `src/app/commandList.ts` with `planned: '<step>'`, and shows greyed out until its step. Release build: installer 1.8 MB, start-up median under 0.7 s. Building needs what the README's Requirements list; Rust from rustup lives in `%USERPROFILE%\.cargo\bin`, which may need adding to PATH in a new shell.

## Speed check before committing

Before offering to commit any change, time what it touches: work out which actions it affects and run `npm run perf -- <actions>` on just those against a fresh release build (`npm run perf -- --list` names them; a change to start-up, saving or drawing the canvas also runs `start`, `save` and `brush`, since everything leans on them). Anything over budget, or flagged `SLOWER` (over 10% slower than the last full audit), gets fixed or explained before the commit, and the reply offering the commit gives the timings, so each change's cost is visible. Full audits, their process and budgets are in [docs/performance-audit.md](docs/performance-audit.md). This keeps Sketch from getting slow one feature at a time.

## Traps

- A window holds several pictures as tabs (F14). `app.doc`, `app.history`, `app.viewport`, `app.file` and the other per-picture fields are getters onto `tabs.list[tabs.active]` (`src/app/store.ts`), and each tab has its own autosave slot. New state that belongs to a picture goes on `Tab`, or it leaks between tabs; something written for later (a timer, an autosave) must hold its `Tab`, not read `app`, since the tab showing may have changed by then. New, Open and launches open a new tab, so a test that wants a fresh picture closes the others (`perf.mjs`'s `newPicture`).
- The app was called Quick Paint until 21 Oct 2026. Its layered files were `.qpaint` with `format: 'quickpaint'`; now `.sktch` and `format: 'sketch'` (no other app uses `.sktch`; `.sketch`, `.skch`, `.sktz` and `.skt` belong to other apps). Opening still accepts the old ones so older files keep working. Keep that fallback.

- Vite's file watcher on Windows sometimes misses an edit made seconds after another to the same file, and keeps serving the old version. If the browser shows code that doesn't match the disk, rewrite the file (read and write it back) and reload.
- In the browser pane, `import('/src/...')` from a test script can load a second copy of the modules after a hot reload (the page's imports carry `?t=` timestamps). Drive the page through real DOM and keyboard events instead, or reload first.
- A test script run right after a reload can send pointer events before the first fit sets the zoom, so they land off the picture and do nothing. Wait a few hundred milliseconds, or read `app.viewport` first.
- The browser pane pauses `requestAnimationFrame` while hidden, so screenshots can show an old frame. Trigger a real input event before taking one.
- `arboard` 3.7 writes PNG, CF_DIBV5, CF_DIB and CF_BITMAP for images, so copies keep transparency; no extra clipboard code is needed.
- `tauri icon` also writes Android and iOS icons; delete `src-tauri/icons/android` and `src-tauri/icons/ios`.
- A paste event's `clipboardData` is emptied once the handler first awaits a Tauri call (the IPC round trip outlasts the event). Read everything needed from it (text, HTML, items) before the first `await`. In a plain browser the bug hides, because the browser fallbacks resolve at once. Link paste was broken this way until 21 Oct 2026.
- Python on Windows writes text-mode files with CRLF line endings; the repo uses LF (Phase 5 and 6 both had to convert). Edit files with binary mode or the Edit tool, and convert any changed file holding `\r\n` before committing.
- Only one Sketch runs per data folder: a second launch hands its command line over a named pipe named after the folder (`src-tauri/src/instance.rs`) and exits. Anything that starts the app for a test must set `SKETCH_DATA_DIR` (`native-driver.mjs` and `startup-check.mjs` do), or its launch goes to the user's own running Sketch and its autosaves mix with theirs.
- The Claude desktop app is a packaged (MSIX) app, so Windows redirects writes to `AppData` from every process a session starts into `%LOCALAPPDATA%\Packages\Claude_<id>\LocalCache`, and those processes see that copy over the real one. Never run Sketch's NSIS installer straight from a session: an install landed there once, its Start menu shortcut kept starting that stale copy, and every update offered itself again. `install.py` reruns itself outside the package, and `hooks.nsh` repoints Sketch's shortcuts at `$INSTDIR` on each install. To look at or change the real install, data folder or shortcuts, run the script outside the package (`Invoke-CimMethod Win32_Process -MethodName Create`) and have it write its output under `Documents`.
- Tauri deadlocks on Windows when a window is built inside a synchronous command, so commands that open windows (`open_window`) are `async`.
- `check:native` (`scripts/native-check.mjs`, helpers in `scripts/native-driver.mjs`) drives the real app; run it after changing anything that touches `src/platform` or `src-tauri`. It needs the release exe (`npm run tauri build -- --no-bundle` is enough) and takes about 3 minutes. It reaches the page through `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=…` with its own `WEBVIEW2_USER_DATA_FOLDER`, and starts the app in its temp folder, so a missed dialog never saves into the project.
- Filling the native file dialogs: UI Automation can't see their file name box, so the driver uses Win32 (the details are in `fillFileDialog` in `native-driver.mjs`). The Save dialog ignores `WM_SETTEXT`, so the path is typed as `WM_CHAR`s.
- In `check:native`, the helpers destructured at the top (`press`, `waitFor`, `state`) belong to the first launch. A check that relaunches must call `app.press` and friends on the new `app`, or it talks to a closed window and waits forever. Every check has a 60 s limit so such a hang fails instead of stalling.
- The browser pane's key action sends some keys without `code` (`bracketright` arrives as an empty key; `?` arrives without Shift), and its screenshots often lag one action behind. `comboOf` falls back to the character for keys without a position; check state by reading the DOM with JavaScript, not from screenshots.
- The window is `transparent: true` so Mica can show through. Rust applies Mica with `window-vibrancy` itself (Tauri's `windowEffects` drops the error), and the page only turns its backgrounds see-through (`html.mica`) when `mica_enabled` says it worked, so Windows 10 gets solid colours instead of an invisible window. Keep both halves.
- Real drag and drop from Explorer can't be scripted without moving the mouse. The check sends Tauri's own `tauri://drag-drop` event with `emit_to` (target `{ kind: 'Webview', label: 'main' }`, position in physical pixels), which covers everything after Windows hands the drop to Tauri.
- Driving the page from the browser pane: its screenshot and click coordinates use an 800 × 600 frame while the page is 1024 × 768, so a click's coordinates are CSS pixels × 800 / `innerWidth`. Scripted `PointerEvent`s with `pointerId: 1` work for drags of any shape (setPointerCapture accepts them), where the click tool only drags straight. In dev builds `window.sketch` holds `app` and `flatten`, for reading pixels and state.
- In the text editor's textarea, set the font with `fontFamily`, `fontSize`, `fontWeight` and `fontStyle`, never the `font` shorthand: Preact only rewrites the style keys that changed, and the shorthand resets `line-height`, so the caret drifts off the drawn text.
- Windows' mouse speed is one setting for the whole PC. Anything that starts the app for a test must set `SKETCH_TEST_MOUSE_SPEED` to a stand-in file (`launch` in `native-driver.mjs` does), or a slider left away from normal changes the user's real mouse speed whenever the test window has focus under their pointer.
- Windows fades a hidden window out, so a screen frozen right after hiding Sketch still shows it. `start_capture` turns the fade off (`capture::set_fade`) while hiding; keep it.
- The capture overlay (`capture.rs`) keeps its state in a `thread_local` `RefCell`, and `panic = "abort"`: `wndproc` only uses `try_borrow_mut`, and makes calls whose messages must reach the state (`DestroyWindow`, `SetCapture`, `ReleaseCapture`) after letting go of the borrow.
- Capture keys belong to the capture helper, `sketch-capture.exe` (`helper.rs`, a second binary of the same package; `tauri build` builds and bundles every binary, and `windows/hooks.nsh` stops it before an install and starts it again after). It keeps running after Sketch closes and adds a sign-in `Run` entry, so anything that sets capture keys for a test must use `SKETCH_DATA_DIR` (the entry becomes a stand-in file) and kill its helper afterwards, as `check:native` does.
- With Sketch closed, every capture starts a hidden Sketch (F12, `--hidden=<id>`; the decisions doc explains the hand-over messages), and every capture notification goes after 3 seconds. A check that counts Sketch processes after a capture must expect that one, and a check that clicks a notification keeps `note-ms.txt` in its data folder (`dataFor` in `native-check.mjs` writes it) or loses it after 3 s. Checks send keys with `SendInput` (F16), which go to whatever window is in front: only keys that type nothing.
- Windows never calls a process's low-level keyboard hook for keys going to that process's own windows, so Sketch's Left Shift watch (F16) runs in a `sketch-capture.exe --shift-tap=<id>` of its own; don't move it back into Sketch.
- Installed Sketch runs from a version folder (`%LOCALAPPDATA%\Sketch\app-<commit>\`, F6), beside the launcher (`src/bin/sketch-launcher.rs`, installed as `sketch.exe`). Anything that starts Sketch or its helper later (shortcuts, the `Run` entry, taskbar pins, the helper opening a capture) must point at the launcher (`layout::launcher_exe`, `--capture-helper`), never at `current_exe()`, or it keeps starting a version that's later deleted. The restart hand-off must start no console program (one would open a terminal window per command); the launcher is a windowed program. Test the layout in a scratch install folder, as `check:update` does.
- With developer updates on (README, "Developer Updates"), each push of `main` builds the pushed Sketch into the real install in the background; never install it by hand after a push. `dev-update.mjs` starts its work through WMI to escape the Claude package (trap above), and shares `update.rs`'s build file names; keep both. Tests of it pass `--install`, `--data-dir` and `--repo` for scratch folders.
- On a whiteboard or a capture, a pixel tool's pointer-down can grow the canvas up or left, which moves every canvas position (the view moves with it, so nothing jumps on screen). A test script that drives several strokes must work out each stroke's screen points after the one before, from positions relative to `frameOf(doc)`; points worked out up front land in the wrong place.
- A popover's "just closed" guard must start at `-Infinity`, not 0: the page's clock starts when the window loads, and checks click within the first half-second, so a guard of 0 swallowed the mouse speed button's first click.
- Shrinking a picture-sized canvas to under half size with `imageSmoothingQuality` `high` (or `medium`) makes the WebView rebuild its downscaled copies every frame: 37 ms a frame at 8K. The renderer's `drawShrunk` halves big canvases with plain smoothing first; draw any new picture-sized canvas through it.
- Handing data from the page to Rust costs about 10 ms per MB (a 4K picture's raw pixels took 0.3 s). Send encoded bytes (PNG, as Copy does with `copy_png`), never raw pixels, for anything picture-sized.
- Copies and captures go on the clipboard through `clip.rs` (PNG first, then CF_DIBV5, as arboard writes them), not arboard's `set_image`, which encoded the PNG slowly. Reading the clipboard still uses arboard.
- The release build is `opt-level = "s"` except the image-coding crates (`png`, `fdeflate`, `image` and friends in `Cargo.toml`), which are built for speed.
